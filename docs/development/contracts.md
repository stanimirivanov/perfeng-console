# Offline contract consumption

The snapshot is prepared directly from signed perfeng-contracts distributions.
The distribution lock binds the exact control-plane alignment receipt and five
independent family selections. The local provenance document records direct
provider identity, selected file hashes and the separately pinned report
supplements. The vendor ledger matches the hash in the control-plane receipt.
Primary bundle 0.21.0 and the existing Native, integration, analysis-publication
and catalogue selections retain their exact bytes.

## Signed updates and recovery

Stage the exact tool and history assets described below. Use a fresh destination
under an operator-owned directory:

```sh
make contracts-update-check CONTRACTS_SHADOW_ASSETS="$assets" \
  CONTRACTS_BOOTSTRAP="$bootstrap" CONTRACTS_VERIFIER="$verifier" \
  CONTRACTS_CONTROL_PLANE_RECEIPT="$receipt" CONTRACTS_STAGING_TARGET="$scratch/current"
```

Review the staged tree before applying it to `vendor/perfeng-contracts`.
The command obtains schemas and examples from the provider's signed artifacts.
It carries the independently reviewed ledger and provenance into the staged
snapshot. A different selection requires a new reviewed receipt and pin update.

Keep the pre-cutover snapshot, its reviewed commit and the signed assets.
The distribution lock records the retained provenance digest for rollback.
Recreate a fresh snapshot and compare it to the retained bytes:

```sh
make contracts-restore-check CONTRACTS_SHADOW_ASSETS="$retained_assets" \
  CONTRACTS_BOOTSTRAP="$bootstrap" CONTRACTS_VERIFIER="$verifier" \
  CONTRACTS_CONTROL_PLANE_RECEIPT="$receipt" CONTRACTS_STAGING_TARGET="$scratch/recovered" \
  CONTRACTS_ROLLBACK_SNAPSHOT="$previous_snapshot"
```

Both commands run in the existing network namespace. All selected signed
closures and receipt pins must pass before staging. The recovery rehearsal
covers distribution rollback at the same contract revisions. Run
`make contracts-check` on the staged candidate in a disposable checkout to
verify that all generated types and validators reproduce identically.

## Generation and validation

make contracts-generate writes reviewed output; make contracts-check verifies
inventory, SHA-256 and complete local reference pointers before comparing
regenerated bytes. Both require Linux util-linux unshare with user/network
namespace support. Hosted Ubuntu denied uid_map writes during the first CI run.
The hosted-only launcher uses sudo solely to create a network namespace, then
setpriv drops to the original runner UID/GID before Node or generator code runs.
It changes no host setting. Developer machines use an unprivileged user/network
namespace. Network access is disabled for Node and its esbuild subprocess.
Node permissions also restrict filesystem reads to this checkout and installed
node_modules; only explicit generation grants writes to src/generated.
Missing namespace support fails the command; there is no networked fallback.

openapi-typescript 7.13.0 generates three API type surfaces. Ajv 8.20.0 and
ajv-formats 3.0.1 generate standalone draft-2020-12 validators. esbuild 0.28.0
bundles their helpers into ESM without runtime compilation. All four packages
are MIT and development-only, selected for Node 26.13.0 and TypeScript 6.0.3.
The lock fixes their complete resolution. No implicit install or runtime schema
fetch occurs. PR4 owns the fixed-origin transport using these operation types.

The selected integration Error component has a root reference plus sibling $defs.
Generation first exposed TS2502 because the generator lost those definitions.
Only the in-memory type-generator input expands component root references with
$defs. Vendor bytes and validator inputs stay unchanged. Compilation guards this
adaptation. Ajv strict schema mode is disabled for OpenAPI metadata; schema,
format and payload constraints remain active, with no coercion, defaults or
removal of extra fields. Validator return values describe schema conformance;
they do not authorize operations or authenticate data.

## Ownership and checks

Only the compiler-owned validators.mjs is exempt from the handwritten unused
variable lint rule because Ajv emits unused context arguments. Other lint rules
remain active. Its bytes are regenerated and compared before lint and tests.
The source boundary admits this exact ESM output and its declaration without
a general JavaScript exception. Do not patch generated output manually.

Tests reject tampered bytes, extra files, remote or undeclared refs and invalid
pointers. Source examples validate while WARN, unknown fields and unsupported
schema versions fail as defined by the selected schemas. Payload inputs are not
mutated. These fixtures never enter production UI observations.
Generated helpers are bundled together; actual browser cost must be measured
when a consumer first imports the needed validator. The product build currently
does not import these validators. Reverting the consumer snapshot changes no
provider schema or platform data.

## Output inventory

src/generated/generated-manifest.json separates compiler-owned output from AGENTS.md.
Checking compares the complete output set. Regeneration preflights all existing
files before changing any of them, refuses unowned or edited files, and removes
only unchanged previously owned outputs that have been retired. Unsafe ledger
paths and symlinks, including output-root ancestors, fail closed. The write command uses an exclusive local lock;
a leftover lock after interruption must be inspected explicitly.
The manifest itself is generated and byte-compared, never hand-maintained.
C7 candidate adoption and source-attestation requirements remain separately pending.

GitHub marks compiler-owned modules as generated and upstream copies as vendored.
The handwritten agent guide, output manifest and source provenance remain visible
review surfaces. This classification reduces review noise; checksums, semantic
receipts and deterministic regeneration remain required and Git conflicts still
need normal source reconciliation.

## Direct-provider shadow comparison

The reviewed [distribution lock](../../contracts-distribution.lock.json) binds
the control-plane selection to its exact merged commit and receipt digest.
Obtain the receipt by running the control-plane shadow gate from that commit.
Stage the history and materializer releases in `history/` and `tool/`
under one private local directory, using the exact tags in the lock. The
bootstrap is a trusted perfeng-environment checkout with its locked Python
environment installed. Use the independently checksum-pinned verifier.

```sh
make contracts-shadow CONTRACTS_SHADOW_ASSETS=/absolute/path/to/assets \
  CONTRACTS_BOOTSTRAP=/absolute/path/to/reviewed/perfeng-environment \
  CONTRACTS_VERIFIER=/absolute/path/to/trusted/gh \
  CONTRACTS_CONTROL_PLANE_RECEIPT=/absolute/path/to/control-plane-selection.json
```

The gate verifies the signed provider closure for each family, compares its
selected bytes to the vendored snapshot, and checks the three API type surfaces
and Ajv output via deterministic regeneration. The snapshot ledger must match
the reviewed control-plane receipt. The report supplements are checked directly
against their separately recorded provider source. The provenance document
records the direct provider and independent alignment and supplement identities.

A changed receipt fails its digest check. To align with a newer control-plane
revision, regenerate its receipt and review the commit, digest, and selections
before changing the pins. Routine verification and the product still use the
existing vendored snapshot. This gate adds no runtime release access.
