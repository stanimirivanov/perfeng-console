# ADR 0002 — UI technology stack for Perfeng Console

**Status** Accepted · **Date** 2026-11-06 · **Scope** M05 browser consumer. ADR 0001 is reserved in the approved proposal for console/BFF ownership.

**Use Angular 22.2.4 with TypeScript 6.0.3, Angular Material, NgRx SignalStore and Effect 4.** Build the browser application with the Angular CLI application builder. Run UI unit and component tests through Angular’s CLI and TestBed with Vitest. Keep Playwright for end-to-end verification. Serve the built browser assets from the planned loopback HTTPS BFF.

**Drop TypeScript 7 from this combination.** The stable TypeScript release checked was 7.0.2. Both `@angular/compiler-cli@22.2.4` and `@angular/build@22.2.6` declare `typescript >=6.0 <6.1`. The existing harness linter also requires TypeScript below 6.1. Keep the repository's exact **6.0.3** pin. Reconsider 7 when stable Angular compiler and CLI build peers, the lint tooling, and the harness compiler-API sensor all support the same exact release. Forced installation, a second application compiler, and disabling version checks are excluded. [Compiler manifest](https://registry.npmjs.org/@angular/compiler-cli/22.2.4) · [Build manifest](https://registry.npmjs.org/@angular/build/22.2.6) · [Lint peers](https://registry.npmjs.org/typescript-eslint/8.72.1) · [TypeScript release](https://registry.npmjs.org/typescript/7.0.2)

## What the screens require

- Catalog pages, health metrics and Scenario Lab matrices need bounded tables, row/column headers, units, denominators, explicit gaps and stable row identities. A partial catalog cannot become selectable. Keyboard users must retain their place during updates. [Lines 421–447][tables], [795–806][matrices]
- The Run screen needs two separate representations: allowed transitions from the pinned graph, and observations actually received. Render observed revisions as a chronological list with gaps. A polling jump supplies no intervening event or duration. [Lines 449–462][timeline]
- Reports require the six §27 sections, accessible verdict labels and UNKNOWN values. Expected/actual differences are structured field comparisons supplied by the evaluator. Render metric, unit, baseline, actual value and finding reason as text. A general HTML/Markdown diff engine adds no evidence. Keep verified artifact links distinct from checksum claims. [Lines 548–561][report], [337–347][lab]
- Approvals need scope, expiry, explicit user action and an outcome that survives reconnect without automatic replay. Distinguish live observations from explicitly opened historical receipts. Preserve keyboard operation, focus visibility and text labels independent of color. [Lines 173–186][session], [355–364][intent], [748–757][cluster], [805–806][a11y]

Material/CDK and NgRx admit Angular 22 and RxJS 7.8.2. The builder admits Vitest 5.1.0 and Node 26.13.0. RxJS is a required peer, not an additional owner of application state. The general Angular compatibility page may describe another minor; the exact compiler and builder manifests govern this proposal. - Verify frozen pnpm install with lifecycle scripts disabled, exact transitive graph/licenses/audit, Node/TS engines, and offline production build after bootstrap. Check generated browser imports and browser-only TS types. Angular templates, stylesheets and CLI workspace files must fit the browser layer. The current architecture sensor admits TS/TSX/CSS/Markdown under src; external Angular HTML or SCSS requires a narrowly reviewed format rule with negative tests, or a template/style placement already permitted. Require browser-owned resource resolution for templateUrl/styleUrl, Sass imports and copied assets. Check the production build graph, all lazy chunks, source maps and served assets for server-only inputs, secrets and test fixtures. A negative fixture that references a BFF resource must fail even when its TS import graph looks legal. No blanket extension or package wildcard. [Harness policy](../../harness/boundaries.ts) · [Plan lines 109–138][foundation]
- Render with the approved CSP. Disable remote font and critical-style inlining where applicable. Inspect the actual HTML, lazy chunks, component styles, Material/CDK overlays and network traffic. Angular documents per-response style nonces for inserted styles. First exercise production output under the existing policy. If Angular inserts component styles that the header blocks, **Angular/Material admission is blocked** until a scoped style-nonce exception is authorized and proven. For that exception the BFF must generate an unpredictable nonce per HTML response, deliver the same value through the CSP style directive and Angular's root nonce attribute, and prevent reuse of nonce-bearing HTML by shared caches. Fingerprinted static JS and external CSS can be cached separately. Test fresh nonces across reloads, a mismatched nonce that blocks styles, and dialog/overlay placement under the actual headers. Never silently broaden policy to unsafe-inline/eval, hard-code a nonce, or enable a generated CSP that widens the agreed policy. A Material overlay requiring a prohibited style operation fails admission. External URLs in evidence may appear as inert text only. As a future blocking extension, `make verify` must invoke the pinned local CLI for `ng build --configuration production` and `ng test --no-watch --no-progress` as well as the existing harness checks. Playwright stays in the real-browser CI gate. Keep Node, Angular and E2E discovery disjoint. Require a nonempty suite, no skipped/todo cases, and retained first failures for each runner. Prove the aggregate fails on an invalid template binding and a failing Angular component assertion. These commands require the planned Angular workspace configuration. Package peers establish compatibility ranges, not runtime proof.

## State ownership and adverse cases

The BFF owns each observation envelope and upstream authority. SignalStore keeps live data only in memory and owns per-session invalidation. Effect fibers execute reads only while the requesting route/session is active. Forward their cancellation signal into the typed transport. Interrupting a fiber cannot undo an already dispatched mutation. Simulator approvals and evaluator findings stay authoritative in their owning process. Effect must not replace generated OpenAPI clients or Ajv validation, introduce a second scheduler/cache, or retry mutations. Browser bundles contain no upstream bearer or privileged adapters. [Plan lines 141–154][client], [157–186][auth], [337–347][lab], [355–364][intent]

Poll active resources at the agreed 5 s cadence with a 3 s read deadline and maximum 10 s validity. Key observations by resource, scope, provider generation and request sequence. On an endpoint failure, advance its local invalidation epoch before clearing the resource. On shared transport failure, advance the provider epoch before clearing all its views. Capture both epochs at dispatch. A delayed success from an earlier epoch must be discarded even when the BFF's generation and the request's resource revision still match. Session or configuration change invalidates all prior subscriptions. Compare the returned revision and immutable fields too: a newer request can return incompatible older data. Respect the BFF's earlier validity bound. For fresh acquisitions conservatively anchor its validity duration to monotonic request start, clear expired values and revalidate on resume before display. A recovered health response cannot restore a report. Only a separately approved, target-verified disposable recovery step may remain available during CP outage. Historical receipts are explicitly dated. [Plan lines 189–203][fresh], [748–757][cluster]

Test the race with two concurrent reads: Health detects loss of provider transport, then an older in-flight Report request succeeds. Report must stay unavailable until its own fresh acquisition. Interrupt the old fiber and also reject its late completion. On direct or forged write requests, the BFF and simulator must independently check current session, capability, target and approval expiry at dispatch. An unavailable provider disables new workload writes. Reconnect cannot replay an uncertain mutation. Test a direct denial and the separately approved recovery path under the same outage.

Use stable keys for rows, derive the allowed state graph from the pinned transitions, and render only observed timeline events. When expiry removes a focused row or disables an action, announce the change once, return focus to a stable heading/status and require fresh selection. Test catalog replacement, zero versus UNKNOWN, conflicting revisions, both expectation levels, and scoped links to actual runs. Material provides controls; the evaluator supplies the result. Verify with real keyboard and screen-reader checks in addition to Angular unit tests. [Plan lines 449–462][timeline], [548–561][report], [795–806][matrices]

## Judgment calls and reversal cost

Angular templates, dependency injection and Material theme tokens are the most expensive choices to reverse after ten screens ship. BFF delivery of per-response CSP nonces, if approved, couples the shell to its host and is another material reversal cost. The NgRx/Effect split adds a second learning cost. Keep transport and effect lifetimes behind narrow interfaces and keep presentation models independent of Angular so changes remain local. I recommend using Effect first for bounded, cancellable read operations and keeping retries for writes disabled. The UI standardization benefits are a judgment about team preference and future maintenance. No team productivity or performance measurements exist yet.

## Adversarial review and remaining evidence

The fresh-context review and the authorized read-only Codex CLI review were reconciled against the agreed plan. Both challenged strict-CSP hosting and the separation of browser and harness compilation. The fresh reviewer also identified resource paths that bypass TS import scanning and the need to reject stale writes at the server. The CLI reviewer supplied the Health/Report race above and pointed out that today's verification aggregate omits Angular compilation and UI tests. All are actionable. The admission gates above specify negative cases for each.

**What survived review:** the published compiler and builder peer ranges exclude TypeScript 7.0.2 and include the current 6.0.3 pin. The exact manifests were read independently by the author using read-only registry queries. The CLI reviewer could not retrieve them, so its review provides no independent confirmation of those pins. Vitest 5.1.0, jsdom 31.0.0 and Playwright Test 1.65.0 declare Node ranges that include 26.13.0. The reviews found no need to move provider credentials, change the generated-client discipline or add another deployment service. Integration and CSP admission remain unverified until the production build and browser tests run. [Vitest manifest](https://registry.npmjs.org/vitest/5.1.0) · [jsdom manifest](https://registry.npmjs.org/jsdom/31.0.0) · [Playwright manifest](https://registry.npmjs.org/@playwright/test/1.65.0)
